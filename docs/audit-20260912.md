# JH7110 镜像工程代码审查（2026-09-12）

审查基线：`0814800e7023736ca6322719bcaa7273107f4e3d`。
范围：仓库构建脚本、CI、rootfs 配置、GPU 二进制包的 ELF 依赖及
SONAME、锁定 BSP 的显示设备树和相关配置。此次不是整个 Linux
内核的逐行审计，也没有连接 VisionFive 2 或 Mars 实板。

## 已修复

| 问题 | 影响与处理 |
| --- | --- |
| GPU postinst 的末尾 `[ -e "$1" ] && update-initramfs ...` | 首次安装尚无 initrd 时整个脚本返回 1，dpkg 配置失败。改为显式条件及成功退出，更新 initrd 的真实失败仍向上传递。 |
| 固件 hook 不处理 `prereqs` | initramfs 探测依赖时会误执行复制。增加标准入口和 DESTDIR 校验，两份精确 BVNC 固件都必须存在；生成后再检查 initrd 文件列表。 |
| 旧 `rc.pvr` 请求 `drm_starfive` | 锁定 6.12 BSP 构建的是 `vs_drm`。systemd 改为只 modprobe GPU，支持内建模块，不再尝试错误显示模块及关机卸载。 |
| 厂商包携带旧 Vulkan loader、通用 GLES 入口 | 移除旧 loader 和通用链接，保留 PVR 命名库，并声明所需 Debian 运行库依赖。已检查 ELF NEEDED 与 SONAME。 |
| 下载中断污染缓存 | 下载到临时目录，完整 SHA256 验证后才进入缓存。 |
| GPU 包缺失仍继续构建 | rootfs 阶段要求恰好一个 GPU 包，显式启用 GPU 服务。 |
| 图形诊断无匹配 dmesg 时提前退出 | 修复 pipefail 路径，继续完整诊断。 |
| 图形诊断误报 | 检查两份固件、真实 GPU 模块、HDMI 连接与启用状态；缺工具、软件 renderer 或无 PowerVR 证据均失败。Vulkan 隔离 IMG ICD。 |
| Release 漏发启动固件 | 两条发布路径补充 `.itb`、`.normal.out`，回归测试实际执行重命名并展开上传 glob。 |

GPU Debian 包版本递增至 `1.19.6345021-3`。

## 性能配置

- 开启内核 LZ4 zram 后端和 swap，配置 zram-tools 使用 LZ4，逻辑
  容量为 RAM 的 25%，按需占用物理内存，显式启用 zramswap。
- XFWM 默认关闭合成，降低当前软件 X11 显示路径的额外重绘开销。
  用户可以在窗口管理器微调中重新启用。

没有修改 GPU/CPU 电压、频率或 HDMI 时序；没有实测性能提升百分比。

## 验证记录

- 9 个 GPU 脚本行为测试：首次安装、initrd 更新失败传播、hook prereqs、
  缺 DESTDIR、硬件输出样本、软件与未知 renderer、缺 HDMI、缺部分固件。
- 5 个启动配置测试、两条 Release 流程的实际资源集合测试、merged-usr
  内核包合并测试通过。
- ShellCheck warning 级别通过，git diff 空白检查通过。
- 两板 profile 校验通过。源锁远程检查通过；仅作为参考的 upstream
  Linux master 已移动，锁定提交仍保持不变。
- 官方 PVR 归档 SHA256 与 sources.lock 一致；检查了 target ELF 依赖
  及 SONAME，厂商 GLES 库自身使用 PVR 专用 SONAME。
- 使用锁定 BSP 的 DTS/include 依赖，Clang 预处理、dtc 实际编译并
  用 fdtget 验证显示节点与内存。BSP 存在 DSP 单元地址、重复寄存器
  地址等既有 dtc 警告；未将其当成已修复或零警告通过。

完整内核、Debian 包、rootfs 和 initrd 的 Linux 构建由 GitHub Actions
继续执行。当前本地主机为 macOS，未声称本地已完成完整镜像构建。
